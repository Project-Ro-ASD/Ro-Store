# Ro-Store v1.0 release gate

This record belongs to `feature/stable-release-v1.0`. The `v1.0.0-rc1` and
`v1.0.0` tags must not be pushed until every applicable gate has evidence.
An unchecked item is not a claim of support.

## Release safety

- [ ] Ro-Store publishes exactly the x86_64, aarch64 and source RPMs with
  `SHA256SUMS`, a component manifest and exact-workflow attestations in an
  immutable GitHub producer release. These GitHub RPMs are unsigned inputs.
- [ ] Ro-Repo accepts that exact producer release and signs all three RPMs in
  its protected `repo-production-signing` environment with the Ro-ASD RPM
  signing subkey `38CB87F6FBD645309432A6E22E02DEE8828B769B`.
- [ ] The centrally signed RPMs pass verification against
  `packaging/repository/RPM-GPG-KEY-ro-asd`, then pass repository publication
  and Fedora 44 installation checks.
- [ ] The deployed Ro-ASD repository metadata signature is verified with
  `REPODATA-GPG-KEY-ro-asd`, fingerprint
  `1715DDA529B9ADB46D47CB389A62B8F9026E75E5`. The deployed source RPM
  checksum and package signature are checked. GitHub release checksums alone
  do not prove a package signer.
- [ ] The tag points to the reviewed merge commit. The immutable producer
  release assets and manifest match the attested build; Ro-Repo's signed
  output and channel package digests are recorded separately.
- [ ] The release candidate is marked as a prerelease. Its RPM release is
  `0.rc1.fc44`, so the final `1.fc44` package upgrades it cleanly.

As of 2026-11-28, Ro-Store has immutable releases enabled but no rulesets or
`main` branch protection. The release job checks that a tag commit is in
`main`; repository administrators must also restrict who can merge changes,
push `v*` tags and edit release workflows. Ro-Repo already has a protected
production signing environment and signing secret names. Its producer
registry does not yet include Ro-Store. The Ro-Store release job requires
curated notes and fails if producer asset checks fail.
The downloaded v0.9.0 x86_64 RPM passed its `SHA256SUMS.txt` check but
`rpmkeys --checksig --verbose` reported only header and payload digests, with
no package signature. Earlier automatic publication therefore does not prove
that RPM signing is already configured.
The project owner has only a Fedora 44 workstation. Ro-ASD hardware acceptance
and a centrally signed candidate remain pending. Do not call a GitHub
producer release an installable signed release.

## Current known limits

Flatpak updates, system-scope Flatpak changes, runtime/driver/codec/extension
mutations, Fedora distribution upgrades and automatic update scheduling remain
disabled or outside v1.0. A signed release must describe these limits plainly.

## Central signing route

Ro-Store is a producer. Its GitHub release publishes unsigned RPMs and source
with hashes, a component manifest and attestations. Ro-Repo is the signing
authority: its protected `repo-production-signing` job uses environment secrets
`RO_REPO_RPM_SIGNING_SUBKEY_B64` and `RO_REPO_RPM_SIGNING_PASSPHRASE` after
producer admission. Ro-Infrastructure can then publish the same signed bytes
through its dev, beta and stable channels. Never copy production private keys
into Ro-Store or claim that a producer GitHub RPM is signed.
