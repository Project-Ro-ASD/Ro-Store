## Current known limits

Flatpak updates, system-scope Flatpak changes, runtime/driver/codec/extension
mutations, Fedora distribution upgrades and automatic update scheduling remain
disabled or outside v1.0. A signed release must describe these limits plainly.

## Signing setup

The release workflow expects protected GitHub Actions secrets named
`RPM_SIGNING_KEY_BASE64` (base64 encoding of the armored private RPM signing
subkey) and `RPM_SIGNING_PASSPHRASE`. Only authorized Ro-ASD key custodians
should provision them. Do not commit private keys or passphrases. Limit who can
change the tag release workflow and who can push `v*` tags. The workflow keeps
the key in temporary files, checks the private subkey against the published
public key, signs both RPMs, then verifies them in an isolated RPM key database
before generating checksums or publishing.
