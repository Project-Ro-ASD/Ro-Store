# Ro-Store v0.8.0 release verification

## Supported scope

- Installed RPM packages and user/system Flatpak applications appear in a searchable inventory with version, architecture, source and installed size. AppStream limits the default RPM view to desktop applications when its metadata is available; all RPM packages remain accessible.
- When the same application is installed from RPM and Flatpak, both installed versions are shown. This does not compare every available catalog source.
- RPM removal shows the DNF5 dependency plan and a removal warning. Flatpak removal warns that user data is retained.
- Recent DNF5 and Flatpak transactions are read-only. DNF5 transaction status and package details can be opened. Flatpak history may omit failed operations and cannot serve as a complete failure log.
- System update candidates are grouped by kernel and repository source.
- The v0.7 safety boundary remains: Flatpak updates and system-scope Flatpak mutations are disabled in the backend and UI. Drivers, runtimes, codecs and extensions are not enabled for installation through this flow.

## Explicitly deferred

- Catalog-wide RPM/Flatpak source comparisons and a unified catalog search.
- Reliable Flatpak failure history, since Flatpak's history data records changes rather than every failed attempt.
- A genuine user application update with a changed OSTree commit. Flatpak update actions stay disabled.
- Forced power loss, network loss, low disk, corrupt journal, daemon crash and recovery fault injection. These can damage an active workstation and require an isolated disposable environment.
- Denied authorization, concurrent mutation and coordinator lock contention under live workloads.
- Executable mocked-backend fault tests and full keyboard, theme, scaling and small-window visual review.

No deferred scenario is claimed as validated by this release. See [the next milestones](../roadmap-after-v0.8.md).
