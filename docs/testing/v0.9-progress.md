# Ro-Store v0.9 validation progress

This is an in-progress record for the `feature/performance-stability-v0.9` branch. It is not a release gate or a claim that v0.9.0 has shipped.

## Implemented so far

- Ro-ASD catalog uses a bounded, atomic disk cache and refreshes over HTTPS. AppStream metadata uses a Fedora-version-specific disk cache, with a warm-cache path that skips a new AppStream parse.
- A unified search page displays separate Ro-ASD RPM, Fedora RPM and user Flathub results. Rows show their source and version, and flag a matching alternative source when application IDs match. The existing package detail and safety checks remain the installation path. User Flathub details now query the real Flatpak permission metadata before enabling installation.
- Catalog and RPM update checks can refresh in the background while the application is open. The update model is owned by the main window so navigating away does not discard a running read.
- System updates are displayed in kernel, graphics driver, firmware and repository groups. This is presentation only; the selected package plan is still produced by DNF5.
- Executable Flatpak backend tests use an isolated external command and temporary user data. They cover rejected unsafe requests, successful verification, failed mutation, failed read, disk-full response, process crash, corrupt recovery journal, coordinator lock and concurrent managers.
- Executable Ro-ASD catalog tests check cached startup after a network failure and rejection of malformed, expired or oversized cache files. Network reads also stop when the catalog exceeds the size limit.
