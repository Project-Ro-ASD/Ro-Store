# Ro-Store v0.6 — System Updates: single-pass Fedora 44 QA

Status: **draft, not ready for release**. This test checks only non-mutating
operations and explicitly confirmed standalone RPM downloads.

## Build and launch

From the Ro-Store checkout (branch `feature/system-updates-v0.6`):

```bash
git pull --ff-only origin feature/system-updates-v0.6 &&
cmake -S . -B /tmp/ro-store-v060-build -DCMAKE_BUILD_TYPE=Debug &&
cmake --build /tmp/ro-store-v060-build --parallel 4 &&
/tmp/ro-store-v060-build/ro-store
```

Do not use a final bare `ro-store` command after a failed build; it can
accidentally run an older binary.

## Grouped checklist

1. Open **Sistem Güncellemeleri** and refresh. All installed Fedora RPMs
   with enabled-repository updates should appear, including kernel candidates.
   Installed and candidate versions may load separately.
2. Select `7zip` and `assimp`. Verify selected size, package count,
   `Seçilenlerin planını incele`, and the collapsible dependency preview.
   `Tümünü seç` should preview one full-system goal, not trigger installation.
   Inspect removals and kernel changes in the DNF5 plan.
3. In **Güncelleme indirme önbelleği** check the selected cache summary:
   already verified vs missing RPMs. The download-only QA path permits at
   most **12 selected packages** and has a **50 MiB estimated RPM-size**
   UI limit; unknown-size packages are excluded from this test.
   These bounds are *not* a guaranteed network quota, because repository
   metadata and other traffic are not included.
4. With the already cached `7zip` and `assimp` selected, run the preview,
   click `Seçilenleri indir`, and approve. Expect `CACHE HIT` and no
   newly downloaded RPMs.
5. For a genuinely new small RPM, download only after reviewing its size.
   Check the live status line, per-file progress bar, staged byte count,
   elapsed time, and **Günlüğü göster / gizle**. The resulting RPM should
   be checked for exact NEVRA and signature before entering the cache.
6. Try cancelling a standalone RPM download before completion. Its incomplete
   RPM must not appear as verified; previously verified RPMs must remain.
   **Never test cancellation of an actual RPM transaction.**
7. Use **Fedora çevrimdışı güncelleme durumu → Durumu denetle**.
   This is `dnf5 offline status` and is read-only.
8. Verify resizing (400×500, 600×500, 1000×650), full-page scroll,
   independent RPM-list scroll, RTL-free Turkish labels and keyboard focus.
   `Temizle` must request confirmation and never touch system DNF caches.

## Release blockers (must not be marked complete based on QA above)

- Single DNF5 daemon **complete-system** goal for the requested package set,
  including conflicts, removals, dependencies and exact download totals.
- Reuse of validated staged RPMs within the solver-approved transaction; do
  not assume the existing standalone download cache is automatically honored.
- Shared transaction mutex with current install/remove/upgrade queue and
  persisted unknown-outcome recovery journal.
- Kernel/critical RPM offline application and a user-confirmed reboot policy.
  Running RPM mutations must never be forcibly killed.
- Fedora 44 testing for interrupted network, process cancellation, disk-full,
  concurrent operations and interrupted daemon communication.
- GitHub Actions RPM x86_64/aarch64 success and explicit release approval.

Until these safeguards are implemented and tested, **do not add a button
that executes an RPM system upgrade or reboots the machine.**
